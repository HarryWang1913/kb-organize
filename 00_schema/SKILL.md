# 知识库整理助手（kb-organize）

## 设计哲学

这套体系源自 Karpathy 的 LLM Wiki 方法论：**知识管理的瓶颈不是阅读，而是记账**。

传统笔记系统的痛点是：人写完就忘了更新索引、补链接、加标签。LLM 擅长的恰恰是这种"记账"工作 — 维护交叉引用、更新摘要、同时修改多个文件。这个 Skill 就是把这套方法论固化成可复用的工作流。

四层架构：

```
原始素材（外部资料）      ← 只读，AI不修改
    ↓ 编译
概念页（概念/）           ← AI维护，含当前判断+时间线
    ↓ 导航
索引层（index.md + sources.md）← 双入口
    ↓ 配置
规则层（00_schema/）      ← AI操作说明书
```

## 工作模式

根据用户输入判断进入哪种模式：

### 模式 A：单文件整理

用户新增了一篇文章，或指定了一个文件要整理。

**步骤：**
1. **Read** 目标文件，理解内容主题
2. **Read** `00_schema/references/tag-taxonomy.md`，确认可用标签
3. **Read** `00_schema/references/templates.md`，获取 frontmatter 模板
4. 为文件添加 YAML frontmatter（如果已有则合并，不覆盖已有字段）
5. 在文件末尾添加 `## 🔗 相关链接` 部分
6. 检查是否有关联的概念页需要更新（在概念页的"相关文档"中添加新链接）
7. 检查 index.md 是否需要添加新条目

### 模式 B：文件夹批量整理

用户指定了一个文件夹，要批量整理。

**步骤：**
1. **Glob** 扫描文件夹下所有 `.md` 文件
2. **Read** `00_schema/references/tag-taxonomy.md` 和 `00_schema/references/templates.md`
3. 抽样 Read 3-5 个文件，理解该文件夹的内容主题和风格
4. 设计该批次的标签方案（可能需要新增标签类别）
5. 如果文件数量 > 10，用 **Agent** 并行处理（每个 Agent 处理一批）
6. 为每个文件添加 frontmatter + 相关链接
7. 如果该文件夹没有 README.md 索引页，创建一个
8. 更新相关概念页和 index.md

### 模式 C：概念页维护

用户要求创建或更新概念页。

**步骤：**
1. Read 目标概念页（如果已存在）
2. Read `00_schema/references/templates.md` 获取概念页模板
3. Grep 搜索 vault 中与该概念相关的所有文件
4. 汇聚要点，创建/更新概念页
5. 确保所有被引用的文件也反向链接到该概念页
6. 更新概念页"当前判断"区块，改写为最新结论
7. 在"时间线"区块追加本次更新记录

### 模式 D：全局索引更新

用户要求更新 index.md 或全局维护。

**步骤：**
1. Read 现有 index.md
2. Glob 扫描全部 `.md` 文件，对比哪些是新增的
3. 将新增文件归类到 index.md 的对应分区
4. 检查是否有孤立文件（无标签、无链接）需要处理

## Frontmatter 规范

每个文件必须有的字段：

```yaml
---
title: "文章的完整标题"
date: YYYY-MM-DD
type: content | concept | collection-index | index | changelog | framework | profile | reference
tags:
  - 内容类型标签
  - 领域标签
  - （可选）系列标签
  - （可选）状态标签
aliases:
  - 别名1
  - 别名2
---
```

可选字段（按需添加）：
- `series`: 系列名称
- `source`: 外部来源 URL
- `author`: 原作者
- `status`: active | draft | archived（文档当前状态）
- `source_origin`: self | wechat | report | class（内容来源）
- `review_cycle`: weekly | monthly | quarterly | none（建议复查频率）

### type 字段取值

| type | 说明 | 典型场景 |
|------|------|---------|
| `content` | 原创内容（文章、视频脚本、文案） | 用户自己写的内容 |
| `concept` | 概念枢纽页 | 跨文档汇聚一个主题 |
| `collection-index` | 集合索引 | 某个文件夹的 README |
| `index` | 全局索引 | index.md |
| `changelog` | 修改日志 | 记录知识库变更 |
| `framework` | 工具/框架/模板 | 方法论模板、SOP |
| `profile` | 个人档案 | about-me |
| `reference` | 参考资料 | 外部文章整理 |

## 相关链接格式

在文件末尾、正文之后添加（用分隔线隔开）：

```markdown

---

## 🔗 相关链接

- 概念页：[[概念/XXX]] | [[概念/YYY]]
- 系列导航：← [[上一篇]] | [[下一篇]] →
- 相关内容：[[相关文章1]] | [[相关文章2]]
- 合集索引：[[所属合集/README|合集名]]
```

**链接选择原则：**
- 优先链接同主题的概念页（最重要）
- 然后是同系列的上下篇导航
- 然后是内容相关的其他文档
- 最后是所属合集/索引

---

## 标签选择原则

1. **每篇文章至少 2 个标签**：一个内容类型 + 一个领域
2. **不超过 6 个标签**：标签太多等于没有标签
3. **优先使用已有标签**：Read `00_schema/references/tag-taxonomy.md` 查看完整列表
4. **需要新标签时**：先在 tag-taxonomy.md 中注册，再使用
5. **层级标签用 `/` 分隔**：如 `领域/技术`、`内容/文章`

## 概念页结构

概念页是知识库的"编译层"，作用是跨文档汇聚一个核心主题。

```markdown
---
title: "概念名称"
date: YYYY-MM-DD
type: concept
tags:
  - 概念
  - 相关标签
aliases:
  - 别名
---

# 概念名称

> 一句话核心定义

## 当前判断
（你现在对这个主题最核心的认知）

## 核心要点
- 要点1（含具体数据）
- 要点2
- ...

## 相关文档
- [[文档1|简短描述]]
- [[文档2|简短描述]]

## 跨领域关联
- [[概念/相关概念1]] — 关联说明
- [[概念/相关概念2]] — 关联说明

## 关键数据
| 数据点 | 数值 | 来源 |
|--------|------|------|
| ... | ... | ... |

## 时间线
- YYYY-MM-DD | 首次建立
```

## 集合索引（README）结构

当一个文件夹包含大量同类文档时，创建 README.md 索引页：

```markdown
---
title: "合集名 — 描述"
date: YYYY-MM-DD
type: collection-index
tags:
  - 索引/（合集类别）
  - 领域标签
aliases:
  - 合集简称
---

# 合集名 — 描述

导语：合集概述（文章总数、覆盖范围）

---

## 1. 来源/分类名

- **作者**：XXX
- **文章数量**：约 N 篇
- **核心主题**：
  - 主题1
  - 主题2
- **代表文章**：
  - [[文件夹/文件名|可读标题]]
  - [[文件夹/文件名|可读标题]]
```

## 处理边界情况

### 文件已有 frontmatter
- **合并**，不覆盖已有字段
- 如果已有 tags，追加新标签（去重）
- 如果已有 aliases，追加新别名（去重）

### 文件已有相关链接
- 检查现有链接是否仍有效
- 追加新链接（去重）
- 不删除用户手动添加的链接

### 概念页已存在
- Read 现有内容
- 在"相关文档"部分追加新链接
- 如果有新的要点，追加到"核心要点"
- 不修改用户手动编辑过的段落

### 大批量文件（>50 个）
- 用 Agent 并行处理，每批 10-15 个文件
- 素材合集类每个子文件夹最多 Read 10 篇（抽样即可）
- 先完成 frontmatter，再统一更新概念页和索引

## 参考文件

当需要查看完整的标签列表时，Read 本知识库下的：
- `00_schema/references/tag-taxonomy.md` — 完整标签体系
- `00_schema/references/templates.md` — 各类型文件的 frontmatter 模板和示例

这两个文件是"活文档"，随着知识库扩展会更新。如果需要新增标签类别，先更新 tag-taxonomy.md。

## 输出规范

每次整理完成后，告知用户：

1. **修改了哪些文件**（列表形式）
2. **新增了哪些文件**（如概念页、索引页）
3. **使用了哪些标签**
4. **建立了哪些链接关系**
5. **如果有需要用户确认的决策**（如新标签是否合适）

用 wikilink 格式引用文件，方便用户在 Obsidian 中点击跳转。
