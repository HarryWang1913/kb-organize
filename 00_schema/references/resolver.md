# 新文件归档分流决策树

归档前先判断四件事：来源、用途、隐私、事实风险。

## 四个问题

1. 来源是什么？
   - 用户原创
   - 外部素材
   - 项目文档
   - 个人过程记录
   - 维护记录
   - 来源不明

2. 用途是什么？
   - active 正文
   - 概念综合
   - 来源导航
   - 项目文档
   - 私人记录
   - 维护证据
   - 暂时无法判断

3. 是否涉及隐私？
   - 客户、合同、证件、联系方式
   - 家庭资产、财务账户、医疗信息
   - 私人日程、执行细节
   - 不确定是否敏感

4. 是否涉及不稳定事实？
   - 产品条款、价格、费率、收益、法规、公司事实、医疗或金融判断。
   - 来源不清楚时写 `待补充资料`。

无法回答时，先进入 `inbox/` 并标记 `待人工确认`。

## 目录分流

| 内容类型 | 应进入 | 不应进入 | 处理规则 |
|---|---|---|---|
| 无法判断归属、来源、隐私或用途 | `inbox/` | `index.md`、`概念/` | 标记 `待人工确认` |
| 全局导航 | `index.md` | 正文目录 | 只放稳定入口 |
| 外部来源导航 | `sources.md` | 原创正文区 | 只管理来源和集合 |
| 维护日志 | `log.md` | 概念页 | 追加式记录 |
| 长期概念、方法论、综合判断 | `概念/` | `inbox/`、外部原文目录 | 需要来源和清晰边界 |
| 用户原创内容 | 用户自定义 active 目录 | 外部素材目录 | 标明原创、草稿、已发布或待确认 |
| 项目需求、工具开发、协作文档 | 项目文档目录 | 概念页直接堆叠 | 用 README 或项目索引承接 |
| 个人日程、复盘、训练、执行记录 | 个人记录目录 | `index.md`、公共模板 | 只做本地目录级关联 |
| 外部素材原文 | 外部素材目录 | 原创正文区 | 默认只读 |
| dry-run、执行记录、复检报告 | `维护记录/` | Vault 根目录 | 按主题子目录归档 |
| 规则、模板、标签、结构参考 | `00_schema/` | 概念页正文 | active 规则放 references |

## 冲突处理

- 同名文件不覆盖，先报告。
- 网盘或 NAS 冲突副本不自动合并。
- 语义重复先提出归并建议。
- 所有建议使用 Vault-relative 路径或 Obsidian wikilink。
